# Data Rules

PostgreSQL on Railway, accessed only through Prisma (`packages/db`).

## 1. Hard rules

- Money: `Int` paisa, field name ends in `Paisa`. No `Float`, no `Decimal` for money.
- IDs: `String @id @default(cuid(2))`. Human-facing ids (order numbers) are separate unique fields.
- Timestamps: every model has `createdAt DateTime @default(now())` and `updatedAt DateTime @updatedAt`.
- Soft delete for catalog data (`archivedAt DateTime?`). Orders are never deleted.
- Order items and orders store **snapshots** (name, SKU, price, address) so later edits never change history.
- Every relation declares `onDelete` explicitly. Every foreign key and every field used in `where`/`orderBy` is indexed.
- Enums for closed sets (statuses, roles, payment methods).
- No raw SQL except in reviewed migrations. Never `$queryRawUnsafe`.

## 3. Migrations

- Local: `pnpm db:migrate --name <what_changed>` (creates + applies).
- Production: Railway pre-deploy runs `prisma migrate deploy`. Nothing else touches production schema.
- Never edit, rename, or delete an applied migration. Fix forward with a new one.
- Destructive changes (drop column/table, change type) use expand → migrate data → contract across two deploys.
- Migrations must apply cleanly on an empty database (CI checks this).

## 4. Seeding

`packages/db/prisma/seed.ts` creates local sample data only: categories, 10 products with variants, one admin (password from local env). Never run against production.

## 5. Backups

Nightly `pg_dump` via GitHub Actions to Cloudflare R2, 30-day retention. Restore steps: `docs/runbooks/restore-backup.md`. Test a restore monthly.
