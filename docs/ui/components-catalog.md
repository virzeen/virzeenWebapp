# Components Catalog

The list of approved building blocks and **when to use which**. Storybook shows the live props; this doc explains the decisions.
Before building anything, check here and in Storybook (MCP `list-all-documentation`). If something is missing, add it here + Storybook first.

### Utilities in `globals.css`

- `scrollbar-none`: rows that scroll with their own controls (the gallery strip and phone row, "Features that perform") hide the scrollbar; they still scroll by touch, wheel and keyboard.
- `max-w-gallery-photo`: the product page's main photo from `lg` is never taller than the screen under the sticky header, so the whole photo and its buttons stay in view.

## 3. Decision rules

- **Action or navigation?** Changes data or opens UI → `Button`. Goes to a URL → `Link`. Never a clickable `div`.
- **Where does feedback go?** Field problem → under the field. Form-level problem → `Alert` at the top of the form (checkout below `lg`: just above "Place order"). Background success → `Toast`. Add to bag → the drawer opens and says "Added to bag". Undo → an inline row where the item was. After a failed submit, focus and scroll to the first error.
- **Why is it disabled?** A disabled control shows the reason next to it ("Choose a delivery address to continue.", "Limit 10 of each").
- **Overlay type?** Needs a yes/no → `Dialog`. A few lines next to a button → `Popover`. Holds content or a flow → `Sheet`. Exceptions: the product page's "View product details" and "Size guide" popups are `Dialog size="lg"` (owner's choice), and the product editor's short forms (New product, Add a style, Edit style, Add photos) are `Dialog`s.
- **New primitive or feature component?** If it has no idea what a product/order is → primitive. If it does → feature component.
- **Variant or new component?** Same structure with different look → add a variant. Different structure → new component.
